# Архитектура

Карта того, что где живёт и кто кого может импортировать. Почему именно так - в
[журнале решений](adr/README.md).

## Окно: восемь зон

```
┌──────────────────────────── 1 ────────────────────────────┐
│  ●●●  [AI amazing-ide ▾]  [⑂ main ▾]              🔍  ⚙   │  шапка
├─────────────┬─────────────┬─────────────┬─────────────────┤
│ roas-radar  │ smooth-...  │ amazing-ide │ amazing-claude  │  вкладки
├───┬──────────┬───┬───────────────────────┬──────────┬───┤
│   │          │   │                       │          │   │
│ 2 │    5     │ 8 │           6           │    7     │ 3 │
│   │          │   │                       │          │   │
├───┴──────────┴───┴───────────────────────┴──────────┴───┤
```

Пути выше - от `apps/desktop/src/renderer/src`. Раскладку собирает
`workbench/Workbench/Workbench.tsx`, и только она знает про все зоны сразу. Виды
боковых панелей и середины держит `workbench/ViewStack`: открытый однажды вид остаётся
смонтированным и прячется, поэтому переключение не теряет прокрутку и состояние.

**Меню проекта и меню ветки - всплывающие панели, как в WebStorm.** Панель - `Popover`
из дизайн-системы на Popover API браузера: верхний слой, закрытие по клику мимо и по
Esc, привязка к кнопке через CSS anchor positioning - без библиотек и своего кода
позиционирования. Внутри - `Menu` с поиском, секциями и навигацией стрелками.
Содержимое монтируется только открытым, поэтому каждый раз свежее. Вопросы с вводом
(имя ветки, адрес репозитория, подтверждение push) - `Dialog` на нативном
`<dialog>`, он живёт снаружи панели: панель закрывается при выборе пункта.

**Проекты.** Меню проекта: новый проект (системный диалог «где и как назвать», пустая
папка), открыть, клонировать (адрес и папка, клон сразу открывается вкладкой);
открытые проекты с путём и недавние - закрытые раньше, до 20 штук. Недавний
открывается только из списка недавних: произвольный путь окно так не откроет.

**Поиск везде** - как Search Everywhere в WebStorm: двойной Shift, ⌘⇧O (файлы), ⌘⇧A
(действия), ⌘⇧F (текст); кнопки в шапке нет, слой поиска - `workbench/SearchLayer`.
Панель сверху по центру окна, вкладки All, Files, Actions, Text; фокус всё время в
поле, стрелки двигают выделение (`ListBox`).
Список файлов проекта главный процесс отдаёт один раз на открытие (`git ls-files`, у
папки без git - обход без тяжёлых папок), имена сравниваются в окне. Текст ищет
главный процесс (`git grep`) после паузы в наборе. Действия IDE собирает
`workbench/actions/`. Найденный файл выбирается, дерево раскрывается до него
([ADR 0007](adr/0007-search-everywhere.md)).

**Git** - в главном процессе через `git` (`main/git/`): текущая ветка, локальные и
удалённые ветки, переключение (удалённая ветка без локальной создаёт отслеживающую),
новая ветка, переход на тег или коммит, Update Project (`pull --ff-only`: разошедшиеся
ветки не сливаются без окна конфликтов), Push с подтверждением (ветка без upstream
публикуется). Force push нет. Имена веток и ревизии проверяются до вызова git - опция
вместо имени в него не попадёт. Ответ git при отказе показывается как есть. Commit -
пока нет: для него нужен свой инструмент со списком изменений. Ветка перечитывается при
возврате в окно - её часто меняют в терминале. Справа от ветки - её PR (`gh pr view`,
номер и значок состояния, нажатие открывает браузер); нет PR, gh или входа в него -
кнопки нет. Записывающие команды (pull, push, переключение, новая ветка, checkout) идут
по очереди на проект, чтения не ждут.

**Дерево файлов** (зона 5). Папка читается при раскрытии, по одному уровню. Иконка
строки - `FileIcon` из дизайн-системы: набор Catppuccin в тонах нашей палитры, выбор по
имени, расширению и папке над файлом, как в VS Code
([ADR 0016](adr/0016-file-type-icons.md)). Имя красится статусом git, как в WebStorm:
изменён - синий, добавлен - зелёный, не в git - лососевый, игнорируется - бурый,
конфликт - красный; папка с изменениями внутри - синяя.
За диском открытых проектов следит главный процесс (`main/fs/project-watcher.ts`,
fs.watch с recursive - FSEvents): пачкой говорит окну, какие папки перечитать и что
поменялся `.git` (`fs:changed` - дерево и ветка в шапке), и перечитывает статус git
(`main/git/git-status-service.ts`), рассылая его окну, если он стал другим
(`git:status`). Статус читается без записи в индекс (`GIT_OPTIONAL_LOCKS=0`), иначе
слежение будило бы само себя ([ADR 0017](adr/0017-disk-watch-and-git-status.md)).

**Процессор и память IDE** - в строке состояния, все процессы вместе (главный, окно,
GPU, служебные), те же цифры, что в «Мониторинге системы». Меряет главный процесс
(`main/usage/`): процессор - Electron, память - физический след из macOS через koffi,
потому что RSS у Electron завышает её в разы. Окно спрашивает раз в секунду, пока его
видно; свёрнутое или закрытое другими окнами не спрашивает
([ADR 0008](adr/0008-resource-usage.md)).

**Claude Code** (зона 7, [ADR 0009](adr/0009-claude-code-gui.md)) - своя реализация, а
не панель amazing-claude-code. Главный процесс (`main/claude/`) находит CLI в PATH
терминала человека (macOS не даёт приложению из Finder его PATH), запускает `claude -p`
в режиме потока JSON по процессу на разговор и собирает поток в ленту: реплики,
размышления, вызовы с результатами, итоги ходов. Вопросы CLI (разрешение, выбор,
план) приходят управляющими запросами и ждут ответа человека без таймеров. Модель,
усилие и режим меняются живому процессу, без перезапуска. Процесс поднимается на первое
сообщение и гасится после получаса простоя; разговор продолжается с `--resume`.
Папке, которой человек не доверился ни в панели, ни в терминальном Claude Code, панель
сначала задаёт вопрос: с `-p` CLI сам не спрашивает и сразу исполняет её хуки.
Сообщение, которое не смогло уйти, ждёт в очереди и уходит само. Выход из IDE ждёт,
пока процессы CLI закроются.

В поле ввода - картинки (вставка, перетаскивание, выбор; уменьшаются до 1568 по
длинной стороне), упоминания файлов по `@` (тот же нечёткий поиск, что в «Поиске
везде», `lib/file-match.utils.ts`; файл раскрывает сам CLI) и команды `!` - их
выполняет панель в папке проекта, а вывод уходит модели перед следующим сообщением
метками `<bash-input>`/`<bash-stdout>`. Своё сообщение можно откатить (разговор, код
или оба - служебные запросы CLI `rewind_conversation` и `rewind_files`) или форкнуть
(`--fork-session --resume-session-at`); форк, который ещё не родился, показывает
историю источника и шов. Под итогом хода - изменённые файлы: откат и возврат по
копиям, которые CLI сделал для сообщения, начавшего ход, и только если файл с конца
хода не трогали. Экраны настроек панели (кнопка в шапке): MCP-серверы (состояние,
вход, вкл/выкл - у живого процесса; добавить и удалить - `claude mcp`), плагины
(`claude plugin`, живые процессы перечитывают их сами) и аккаунты - отдельные
хранилища входа CLI (`CLAUDE_SECURESTORAGE_CONFIG_DIR`), вход через Терминал,
аккаунты amazing-claude-code подхватываются без повторного входа. CLI экранов идёт в
папке проекта только после доверия к ней, ключи из адресов и аргументов в окно не
уходят, каждое действие отвечает и списком после себя. Лимиты подписки (пять часов,
неделя, неделя модели, доплата) - на карточке каждого аккаунта и индикатором у поля
ввода: `main/claude/usage/`, ответ CLI на `get_usage` у живого разговора после хода,
иначе своим процессом CLI в постоянной папке конфига аккаунта. Рядом с кольцами - «tok»,
токены за сегодня по всем проектам машины (`usage/today-tokens.ts`): из транскриптов CLI,
изменённых с полуночи, с дочитыванием только нового; на диске он ничего не хранит.
Статистики в панели нет - она своя у IDE, видом середины окна (ADR 0010, ADR 0015).
Поиск по разговорам - `main/claude/search/` (своё подключение в `main/index.ts`, каналы
`claudeSearch:*`): индекс слов человека и модели по проекту в памяти и копией в userData
(`claude-search/`), транскрипты дочитываются с места остановки, свой BM25; резка слов -
одна на обе стороны (`shared/claude-search-words.ts`). Вопрос модели - отдельный
`claude -p` над разговорами текстом. В окне - `SearchWindow` поверх панели, капсула и
подсветка в ленте (`SearchCapsule`, `search-feed.hooks.ts`).
Сценариев в панели нет - они свои у IDE, видом середины окна
([ADR 0014](adr/0014-scenarios-ide-level.md), [ADR 0015](adr/0015-main-area-views.md)).
Вкладки разговоров привязаны к папке проекта и хранятся в `claude.json`; прошлые
разговоры и их ленты читаются из транскриптов CLI (`~/.claude/projects`). Окно
(`features/claude-code`) держит состояние и ленты в кэше React Query: изменения ленты
приходят пачками событием `claude:feed`, по id элементов. Разметка ответа - лексер
`marked` и свой рендер без `innerHTML`, подсветка кода - shiki с ролями
`--color-syntax-*`, плавное появление текста - `smooth-stream-text`. Поверх marked -
свои расширения (`markdown-lexer.ts`): заборы кода по правилу ACC (закрывает только
голый забор той же длины, так блок держит блок) и формулы `$…$`, `$$…$$`, `\(…\)`,
`\[…\]` со строгими границами; KaTeX и его стили грузятся при первой формуле
(`formulas.ts`).
Пути в тексте ленты - ссылки (`paths.utils.ts`, `PathLink`, `LinkedText`): узкое правило
формы плюс список файлов проекта, с `строка:колонка` и диапазонами. Куда ведёт путь,
решает главный процесс (`fs:locatePath`, `main/fs/path-locator.ts`): файл проекта
выбирается с местом (`selection.store`), папка показывается в дереве, голое имя
ищется по файлам проекта (несколько - выбор), вне проекта - системой
(`fs:openOutside`; исполняемое только показывается в Finder), сетевые пути - нет.

**Удалённого доступа с телефона пока нет**: из панели он убран, на уровне IDE его ещё не
сделали ([ADR 0013](adr/0013-remote-access-ide-level.md)). Панельная версия по протоколу
ACC - в локальной ветке `archive/panel-remote-access`.

## Части кода и кто кого импортирует

Правило держит линтер (`boundaries/dependencies` в `eslint.config.mjs`), нарушение -
ошибка, а не предупреждение.

| Часть       | Где                           | Может импортировать                                                           |
| ----------- | ----------------------------- | ----------------------------------------------------------------------------- |
| `ui`        | `packages/ui/src`             | только себя                                                                   |
| `shared`    | `apps/desktop/src/shared`     | только себя. Ни Electron, ни Node, ни React                                   |
| `main`      | `apps/desktop/src/main`       | `main`, `shared`                                                              |
| `preload`   | `apps/desktop/src/preload`    | `preload`, `shared`                                                           |
| `lib`       | `renderer/src/lib`            | `lib`, `shared`                                                               |
| `state`     | `renderer/src/state`          | `state`, `lib`, `shared`                                                      |
| `feature`   | `renderer/src/features/<имя>` | свою фичу, `state`, `lib`, `shared`, `ui`, `locales`. Соседнюю фичу - никогда |
| `workbench` | `renderer/src/workbench`      | всё, кроме `app`                                                              |
| `app`       | `renderer/src/app`            | всё в окне                                                                    |

Отсюда два следствия, которые чаще всего забывают:

1. **Фичи не знают друг о друге.** Что-то нужно двум фичам - это данные в `state/`
   (как выбранный файл: его читают дерево, редактор и строка состояния) или
   композиция в `workbench/`.
2. **Окно не трогает Node и Electron.** Всё через `lib/ipc.ts`.

## Дизайн-система

`packages/ui` - отдельный пакет: токены, база и примитивы (список - в его
[README](../packages/ui/README.md)). Стиль - плоское тёмное стекло: на чёрной раме окна
только шапка, всё под ней - графитовые листы с зазором между ними (вкладки, полосы
иконок, панели, редактор, строка состояния), оранжевый акцент
([ADR 0006](adr/0006-design-system-flat-glass.md)). Сырые значения в стилях запрещает
stylelint: цвет, шрифт, отступ, радиус, слой - только токеном, и токен должен
существовать.

**Витрина** - все токены и компоненты на одном экране (`features/showcase`). Открывается
действием поиска везде «Show or Hide Design System» (⌘⇧A) и ложится поверх панелей. Есть только в dev и в копии окна
агента: в релизной сборке флаг ложен на этапе сборки, и код витрины в бандл не попадает.

## Обновления

Установленная IDE раз в четыре часа смотрит манифест последнего релиза и, если есть
версия новее, показывает уведомление. По кнопке качает zip, сверяет размер и
контрольную сумму, проверяет, что новая версия подписана тем же сертификатом, что и
установленная, подменяет себя и перезапускается. Почему не electron-updater и что
проверено - [ADR 0004](adr/0004-self-update.md). Как выпустить релиз -
[releasing.md](releasing.md), подпись - [code-signing.md](code-signing.md).

## Открытые вопросы

- **Claude Code: что из ACC не переносится** ([ADR 0010](adr/0010-claude-code-acc-parity.md)):
  голосовой ввод (решение владельца), десять языков (интерфейс английский), заставка
  загрузки, раскладки поля слева и справа, анонимная статистика использования (внешний
  сервис ACC), удалённый доступ с телефона - переедет на уровень IDE
  ([ADR 0013](adr/0013-remote-access-ide-level.md)), сценарии - тоже
  ([ADR 0014](adr/0014-scenarios-ide-level.md)). Ждут проверки вживую: моды CLI.
- **Большие папки.** Дерево рисует все строки; для папок на тысячи элементов нужна
  виртуализация.
- **Иконка приложения.** Пока стандартная иконка Electron.
