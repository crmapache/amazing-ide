# 0003. Один типизированный контракт IPC, состояние у главного процесса

- **Статус:** Принято
- **Дата:** 2026-10-15

## Контекст

В claude-code-ide запросы окна шли через один канал с `switch` на ~70 веток, данные
в preload были `unknown`, а типизированные обёртки жили только на стороне окна.
Опечатку в имени поля ловили в рантайме. Подписки сначала не отписывались, и экраны
копили слушатели.

Вторая проблема - кто владеет данными. Открытые проекты меняются и из окна (кнопка),
и из меню приложения (Cmd+O), а окно должно показывать одно и то же.

## Варианты

**Канал на запрос, типы на каждой стороне свои.** Просто, но стороны расходятся.

**Один контракт в `shared/`, из которого выводится всё остальное.** Тип запроса и
ответа на каждый канал, список каналов для preload, тип обработчиков для главного
процесса.

## Решение

Второе. `apps/desktop/src/shared/ipc/contract.ts`:

- `InvokeContract` - запрос-ответ, `EventContract` - события из главного процесса.
- Главный процесс регистрирует обработчики объектом типа `InvokeHandlers`:
  пропустить канал нельзя, ошибка компиляции.
- Preload пропускает только каналы из списка `INVOKE_CHANNELS` / `EVENT_CHANNELS`,
  а `satisfies` не даёт списку разойтись с типом.
- Окно зовёт главный процесс только через `lib/ipc.ts`; подписка возвращает отписку,
  хук `useIpcEvent` отписывается сам.

Владение данными:

- Предметные данные (проекты, содержимое папок, статус обновления) принадлежат
  главному процессу. Окно держит их в кэше React Query под одним ключом на сущность
  (`state/query-keys.ts`). Пишут туда ответ на запрос, ответ на действие и событие -
  без второй копии где-либо ещё.
- Интерфейсное состояние (раскладка, раскрытые папки, выбранный файл) - в Zustand с
  сохранением. Используется одной фичей - лежит в фиче, несколькими - в `state/`.

## Последствия

- Новый канал - три места: контракт, список каналов, обработчик. Компилятор не даст
  забыть ни одно.
- Обработчик в главном процессе тонкий: разобрал и проверил запрос, позвал сервис.
  Логика - в сервисах, чистые переходы - в функциях без Electron, покрытых тестами
  (`workspace-state.ts`).
- Данные из окна проверяются в главном процессе: пути - на выход за корень проекта,
  отправитель - на то, что это окно IDE, а не чужая страница (пригодится, когда
  провайдеры принесут свои webview).
