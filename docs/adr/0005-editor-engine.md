# 0005. Движок редактора: Monaco, а не CodeMirror 6

- **Статус:** Принято
- **Дата:** 2026-10-16

## Контекст

Зона 6 - полноценный редактор кода. Главная идея IDE - лёгкость и скорость, поэтому
выбор делали замером, а не по репутации. Подсказки, переход к определению,
диагностика придут от языковых серверов (LSP), так что сравнивается ядро редактора:
правка, подсветка, работа с большими файлами.

Отдельно важно: в проектах, которые будут открываться в IDE, много больших файлов. В
roas-radar 19 файлов TypeScript длиннее 2 000 строк, в amazing-claude-code 15 (самый
большой - 7 634 строки). И весь код написан без точек с запятой (Prettier `semi: false`).

## Варианты

**CodeMirror 6.** Модульный редактор, собирается из пакетов.

- Плюсы: в 10 раз меньше, вдвое быстрее старт, в 3-4 раза меньше памяти. Настоящее
  синтаксическое дерево (Lezer) без языкового сервера: сворачивание, отступы,
  структурное выделение. Тема - обычный CSS, прямо на токенах дизайн-системы.
  Официальные клиент LSP (`@codemirror/lsp-client`) и сравнение версий
  (`@codemirror/merge`). Прошлая попытка IDE (claude-code-ide) была на нём.
- Минусы: задержка ввода зависит от того, как парсер справляется с файлом, и на
  нашем стиле кода он справляется плохо (ниже). Миникарты и липких заголовков нет,
  остальное собирается из пакетов и сторонних расширений.

**Monaco 0.57.** Редактор из VS Code.

- Плюсы: задержка ввода стабильно 3 мс на любом файле: подсветка построчная (Monarch)
  и не зависит от разбора всего файла. Весь опыт правки VS Code из коробки: поиск и
  замена, мультикурсор, сворачивание, миникарта, липкие заголовки, редактор
  сравнения версий (нужен для просмотра правок от LLM). С 0.55 - встроенный клиент
  LSP, с 0.56 - сборка по частям: подключаются только нужные функции и языки.
- Минусы: тяжелее во всём, что не про ввод. Тема задаётся в JS шестнадцатеричными
  цветами, а не CSS-переменными. Работает через web worker, глобальные сервисы
  внутри, глубоко кастомизировать сложнее.

## Решение

Monaco. В IDE человек больше всего ощущает задержку ввода, а у CodeMirror она на
нашем коде нестабильна: в обычных файлах 7 мс, но на длинных файлах без точек с
запятой и с комментариями - 24 мс, это уже заметно на экране 120 Гц. Monaco держит
3 мс везде. Цену веса снимаем ленивой загрузкой: редактор подгружается при открытии
первого файла, а не при старте окна.

## Факты и замеры

Стенд - `bench/editor` (как запустить - его README). Electron 44.7.2, Chromium 152,
MacBook Pro M1 Pro, 16 ГБ. Оба движка с одинаковым по смыслу набором правки и
подсветкой TypeScript, автодополнение и миникарта выключены у обоих, Monaco - без
встроенного языкового сервиса. Каждое измерение - новое окно, 5 прогонов, медианы.
Ввод: 60 нажатий через `sendInputEvent`, задержка от `keydown` до кадра с результатом.

**Откуда 24 мс у CodeMirror.** Разбор по фазам показал: сам редактор тратит на
нажатие меньше миллисекунды, голый CodeMirror без языка - 1,8 мс. Время уходит на
повторный разбор TypeScript парсером Lezer, синхронно, до 20 мс на нажатие (его
бюджет), остальное - фоном, мешая следующим нажатиям. Без языка - 6 мс, а
убрать любое другое расширение почти ничего не меняет (22-26 мс).

Почему разбор дорогой, нашли бисекцией (`node bench/editor/parse-cost.mjs`): дорого,
когда строки без точки с запятой соседствуют с комментариями. Тогда парсер не может
переиспользовать дерево до места правки, и цена растёт с позицией в файле. На 2 000
простых строк, правка на 90% файла, в разных прогонах:

- без `;`, комментарий в конце строки - 20-55 мс;
- с `;`, тот же комментарий - 1-4 мс;
- без `;`, без комментариев - 2-5 мс.

Настоящие файлы в стенде прошли лучше сгенерированного, но цена зависит от формы
кода, и предсказать её для конкретного файла нельзя.

Ещё одна находка: грамматика Lezer не разбирает предикат типа в стрелочной функции
(`(item): item is T =>`), в App.tsx она находит 22 места, которые не понимает.

## Последствия

- Подключение по частям, без полного `monaco-editor`: ядро `monaco-editor/editor/editor.api`,
  функции правки `monaco-editor/features/register.all` (или выборочно), определения
  языков `monaco-editor/languages/definitions/*` - они грузятся лениво, по языку.
  Встроенные языковые сервисы (`languages/features`, TypeScript worker) не
  подключаются: интеллект кода - через LSP.
- Редактор - отдельный ленивый чанк зоны 6: окно IDE стартует без него, Monaco
  догружается при открытии первого файла. Один экземпляр редактора, по модели на
  открытый файл.
- Тема Monaco собирается из токенов дизайн-системы при старте и при смене темы:
  читаются CSS-переменные и передаются в `defineTheme`. Отдельных цветов для
  редактора в коде не появляется.
- Monaco работает через web worker. В стенде страницы грузились через свою схему; как
  воркер поведёт себя с `file://`, на котором сейчас грузится окно IDE, - проверить
  при встраивании, при проблеме перевести окно на свою схему.
- Пересмотреть, если Lezer перестанет перечитывать дерево на коде без точек с запятой
  (повторить `parse-cost.mjs`) или если вес Monaco станет заметен на старте окна,
  несмотря на ленивую загрузку.
