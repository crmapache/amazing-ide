# 0027. Файл вне проекта по ссылке из ленты открывается вкладкой своего редактора

- **Статус:** Принято
- **Дата:** 2026-10-25

## Контекст

Ссылка на путь в ленте Claude Code («Open in the editor» у вызова READ, путь в ответе)
открывала файл проекта во вкладке редактора, а файл вне проекта отдавала системе: Markdown
из `~/.claude/projects/…` открывался в чужом приложении. Агент постоянно читает и пишет такие
файлы - планы, память, файлы соседнего репозитория, - и владелец попросил открывать их в
самой IDE, как это делает JetBrains с любым файлом.

Редактор был устроен вокруг проекта: ключ вкладки - путь от корня, `fs:readFile` и
`fs:writeFile` принимали только такой путь и отказывали всему, что выходит за корень, слежение
за диском видело только папку проекта. ADR 0018 уже знал один случай «за проектом» - ссылку
внутри проекта, ведущую наружу: она открывается, но пишется только по ⌘S.

## Варианты

**Оставить системе.**

- Плюсы: ничего не менять, главный процесс по-прежнему не читает ничего за проектом.
- Минусы: ровно то, на что жалуется владелец, - файл уходит в чужую программу, ссылка в
  IDE ведёт из IDE.

**Открыть файл как проект или его папку как проект.**

- Плюсы: редактору не нужно знать про файлы вне проекта.
- Минусы: клик по ссылке открывал бы новую вкладку проекта со своим деревом и разговорами -
  слишком тяжело для «посмотреть план».

**Вкладка редактора по абсолютному пути внутри текущего проекта.**

- Плюсы: файл открывается там же, где человек работает, с подсветкой, местом в файле и
  сверкой с диском, как файл проекта. Ключ вкладки - абсолютный путь: путь от корня никогда не
  начинается с «/», так что одна проверка отличает их везде.
- Минусы: главный процесс теперь читает по просьбе окна любой обычный файл до 20 МБ, который
  может прочитать человек. Нужно своё слежение за диском и решение, сохранять ли такой файл
  сам.

## Решение

Текстовый файл вне проекта открывается вкладкой редактора по абсолютному пути, в текущем
проекте. Папка, картинка, PDF и архив по-прежнему уходят системе (исполняемое - только
показом в Finder). Главная причина - просьба владельца: файл, который агент назвал, должен
открываться в IDE, а не в чужой программе, и закрыть это можно, не превращая клик в открытие
нового проекта.

Детали, которые легко потерять:

- `fs:readFile` и `fs:writeFile` - те же каналы, у запроса ровно одно из двух: `relativePath`
  (проект) или `absolutePath` (вне проекта). Путь от корня по-прежнему отказывает всему, что
  выходит за корень: абсолютный путь не принимается в нём молча. Абсолютный проверяется заново
  в главном процессе (`outsidePath`: абсолютный, не сетевой, без управляющих знаков, не длиннее
  предела), остальное - те же проверки, что у файла проекта (без ожидания, обычный файл,
  потолок, не бинарь);
- сохраняется **только по ⌘S** или кнопке Save над кодом, как ссылка за проект по ADR 0018: за
  проектом нет git-страховки и списка изменений, а это часто живые настройки других
  программ. Главный процесс отказывает записи без просьбы человека (`outside`) сам, даже если
  окно по ошибке попросит автосохранение;
- текст или нет, решает `fs:locatePath` по началу файла (`opensAsText`: без нулей, валидный
  UTF-8, не больше потолка). Путь - в NFC, как пути дерева: один файл из ссылки агента и из
  Finder - одна вкладка;
- за диском следит `main/fs/outside-watchers.ts`: окно присылает весь набор открытых файлов вне
  проекта (`fs:watchOutside`), слушается папка файла без recursive - сохранение через
  временный файл и переименование иначе обрывало бы слежение. Правка приходит тем же
  `fs:changed` проекта вкладки, абсолютным путём в `files`. Предел - 64 папки, сверх него
  вкладка сверяется по возврату в окно;
- ссылка из Markdown вне проекта разрешается в абсолютный путь, `/x` в нём - путь от корня
  диска. Картинки такого Markdown пока не показываются (подпись «вне проекта»).

## Факты и замеры

Замеров скорости нет: открытие идёт тем же путём, что у файла проекта. Проверено тестами на
настоящей файловой системе: чтение и запись вне проекта (`text-file.outside.test.ts`),
определение текста и NFC (`path-locator.test.ts`), слежение с сохранением через
переименование и сменой набора (`outside-watchers.integration.test.ts`).

## Последствия

- Ключ вкладки бывает абсолютным: всё, что читает ключи вкладок, отличает их через
  `isOutsidePath` (`lib/path.utils.ts`). Подсказка вкладки и строка состояния показывают такой
  путь через `~`.
- Чтение за проектом расширилось до любого текстового файла человека - держится на
  изолированном окне (`sandbox`, проверка отправителя) и том, что путь приходит только из
  нажатой ссылки. Пересмотреть, если окно начнёт показывать чужое содержимое без изоляции.
- Не сделано и может понадобиться: картинки Markdown вне проекта из его же папки; файл вне
  проекта, лежащий в другом открытом проекте, мог бы открываться в том проекте.
