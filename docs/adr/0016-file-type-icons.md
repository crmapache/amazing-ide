# 0016. Иконки типов файлов - набор Catppuccin в тонах нашей палитры

- **Статус:** Принято
- **Дата:** 2026-10-20

## Контекст

Дерево файлов рисовало одну серую иконку на все файлы и одну на все папки. Владелец
попросил, как в WebStorm и VS Code: по иконке и цвету сразу видно, что это за файл.
Иконок нужны сотни (языки, конфиги, менеджеры пакетов, особые папки), и к ним - правила,
какой файл какой иконкой показать. Рисовать это самим - месяцы работы, а lucide (наши
иконки интерфейса) таких иконок не имеет. При этом дизайн-система запрещает чужие цвета
в обход токенов (ADR 0006).

## Варианты

**Material Icon Theme (MIT, самый популярный набор VS Code).**

- Плюсы: больше всех иконок и привязок.
- Минусы: залитые плашки сочных цветов из своей палитры - на нашем плоском тёмном стекле
  это пёстрые наклейки. Цвета зашиты в каждую картинку, переложить их на токены можно
  только по таблице сотен оттенков.

**vscode-icons (MIT).**

- Плюсы: тоже огромный набор.
- Минусы: те же залитые многоцветные картинки с градиентами; градиенты дизайн-система
  запрещает.

**Catppuccin Icons (MIT): контурные иконки на 16 пикселей.**

- Плюсы: тонкие линии без заливок и градиентов - ровно наш плоский стиль. Каждая
  иконка рисуется 16 именованными цветами Catppuccin (есть вариант картинок с
  переменными CSS вместо цветов), поэтому весь набор перекрашивается таблицей из 16
  строк. Привязки - как у VS Code: имя файла, расширение (самое длинное раньше), папка.
- Минусы: иконок заметно меньше, чем у Material (655); две картинки используют маску и
  градиент - их приходится выбросить или упростить.

**Своя маленькая подборка на lucide.**

- Плюсы: ни одной чужой картинки.
- Минусы: lucide не знает ни TypeScript, ни Docker, ни pnpm - получились бы десять
  одинаковых листков с буквами, это не то, что просили.

## Решение

Catppuccin. Его контурный плоский стиль совпадает с нашим, а цвета у него не зашиты, а
названы - поэтому иконки живут в нашей палитре через токены, а не рядом с ней.
Генератор (`packages/ui/scripts/generate-file-icons.mjs`, `pnpm icons:generate`) берёт
картинки и привязки из релиза по тегу, перекладывает 16 цветов Catppuccin на 11 ролей
`--color-file-icon-*` и пишет один файл данных. Рисует примитив `FileIcon`.

## Факты и замеры

- Набор: 655 иконок из 656, выброшена одна (`wally` - маска, перенести без потерь
  нельзя), у `poetry-lock` выброшен один залитый градиентом элемент. 1087 имён файлов,
  733 расширения, 421 имя папки. Свои привязки поверх: `p12` - сертификат, `lock` -
  замок, `diff` (у Catppuccin он только через язык VS Code).
- Данные - 371 КБ JSON строкой в бандле окна; разбор `JSON.parse` - 1,8 мс (Node 24, M-серия).
  Повторить: разобрать строку из `file-icon-set.generated.ts` в цикле.
- Картинка иконки собирается в элементы React один раз на имя: в дереве сотни строк,
  а разных иконок - десятки.
- Проверено глазами в копии окна (`/dev`): дерево этого проекта и образец в витрине.

## Последствия

- Иконка файла или папки в интерфейсе - только `FileIcon` из `@amazing-ide/ui`, не lucide:
  дерево, поиск везде (файлы и найденный текст), подсказка «@», чипы файлов и папок в
  Claude Code, открытый файл под полем ввода, файлы хода, выбор файла по ссылке. Два
  размера: md (16) - дерево и списки, sm (14) - строка текста и чипы. Lucide остаётся
  там, где значок говорит не о типе файла: «не уйдёт с сообщением», картинка, команда.
- `file-icon-set.generated.ts` руками не правят: поменять привязку или обновить набор -
  правка генератора или тега и `pnpm icons:generate`. Текст лицензии MIT едет внутри
  данных (поле `license`).
- Тона иконок - роли `--color-file-icon-*`. Голубой и розовый смешаны из палитры: своих
  ступеней для них нет, а без них Go, Docker и Sass сливались бы с синими и
  фиолетовыми иконками.
- Пересмотреть, если понадобится светлая тема (тона - отдельные роли, их можно задать
  заново) или если Catppuccin перестанет выпускать вариант с переменными CSS.
