# 0002. Монорепо, дизайн-система отдельным пакетом, границы - линтером

- **Статус:** Принято
- **Дата:** 2026-10-15

## Контекст

Прошлая попытка IDE (claude-code-ide) расползлась. Файлы доросли до 2-3,5 тысяч
строк (`panel/App.tsx` - 3550, `hub.ts` - 2356, `Composer.tsx` - 2016), главный
процесс импортировал протокол из рендерера, GUI Claude Code был скопирован из
плагина и разошёлся с оригиналом. Правила в CLAUDE.md (90 КБ) не удержали: правило,
которое держится на внимательности, рано или поздно нарушают.

Требование к новому проекту: строгая дизайн-система, правила деления компонентов,
никакой лапши и дублей.

## Варианты

**Одно приложение, правила - текстом.** Быстро стартовать, но это ровно то, что уже
не сработало.

**Монорепо, границы держат инструменты.** pnpm workspace: `apps/desktop` и
`packages/ui`. Кто кого импортирует, размер файла, сырые значения в стилях,
строки в JSX - всё это проверяет линтер и ломает проверку, а не предупреждает.

## Решение

Второе.

- `packages/ui` - дизайн-система отдельным пакетом. Импортировать приложение она не
  может физически, примитивы подключаются по одному (`@amazing-ide/ui/Button`), без
  barrel-файла.
- Внутри окна - части `app`, `workbench`, `features/<имя>`, `state`, `lib`,
  `locales` с правилами импорта (`eslint-plugin-boundaries`). Фича не видит соседнюю
  фичу. Карта - в [architecture.md](../architecture.md).
- `max-lines`: 200 строк на `.tsx`, 300 на `.ts` (без пустых и комментариев). Перерос
  - делить, а не поднимать лимит.
- stylelint: цвета, шрифты, отступы, радиусы, слои, тени и длительности - только
  токенами из `packages/ui/src/styles/tokens.css`.
- В JSX запрещены inline-стили (кроме по-настоящему динамических значений с явным
  `eslint-disable` и причиной), inline `<svg>`, текст без i18n и `React.FC`.
- Хук Claude Code после каждой правки прогоняет линтер по изменённому файлу и
  возвращает ошибки агенту сразу (`.claude/hooks/lint-file.sh`).

## Факты и замеры

Проверено подложенными нарушениями: импорт соседней фичи, workbench из фичи, state из
главного процесса, дизайн-система из главного процесса, приложение из дизайн-системы,
`electron` из окна, inline-стиль, текст в JSX - каждое дало ошибку линтера. В стилях
`#fff`, `13px` в font-size, `4px` в padding, `transition: all` и класс не в camelCase
тоже падают.

## Последствия

- Добавить новую папку верхнего уровня в окно - значит вписать её в `ELEMENTS` в
  `eslint.config.mjs`, иначе импорт из неё упадёт.
- Нужного токена нет - его добавляют в `tokens.css`, а не пишут число на месте.
- TypeScript 6, а не 7: typescript-eslint пока поддерживает только `<6.1`, а типовые
  правила (`no-floating-promises`, `no-misused-promises`) важнее скорости проверки.
  Пересмотреть, когда typescript-eslint поддержит 7.
