# 0001. Оболочка на Electron, а не Tauri

- **Статус:** Принято
- **Дата:** 2026-10-15

## Контекст

Главная идея IDE - лёгкая и быстрая, в противовес WebStorm. Интерфейс на React.
Пока только macOS, потом Windows и Linux. В правой панели будут GUI провайдеров LLM,
первый - Claude Code; его хост (запуск CLI, сессии, разрешения) уже написан на
TypeScript в прошлой попытке IDE (claude-code-ide, `main/hub`). Дальше понадобятся
терминал, слежение за диском, языковые серверы - почти всё это живёт в экосистеме Node.

## Варианты

**Electron.** Chromium плюс Node в главном процессе.

- Плюсы: один язык на всё; node-pty, вотчеры, LSP-клиенты, Agent SDK работают как
  есть; код хоста Claude Code из claude-code-ide переносится, а не переписывается.
  Одинаковый движок на всех платформах. Сборка, подпись и выпуск уже отлажены в
  snakein - тем же путём идём и здесь.
- Минусы: базовая память и размер приложения заметно больше, чем у Tauri.

**Tauri 2.** Системный WebView (на маке WKWebView) плюс бэкенд на Rust.

- Плюсы: приложение в разы меньше, память в покое ниже, свой механизм обновлений.
- Минусы: второй язык во всём проекте; хост провайдеров, терминал и прочее пришлось
  бы писать на Rust или таскать Node отдельным процессом рядом (и тогда выигрыш в
  памяти частично съедается). На Linux WebView - WebKitGTK, известный медленной
  отрисовкой; на Windows - WebView2. Три разных движка вместо одного.

## Решение

Electron. Тяжесть WebStorm - это JVM и индексация, а не оболочка: VS Code на
Electron тоже воспринимается лёгким. Лёгкость здесь обеспечивает дисциплина внутри
оболочки (одно окно, ленивые виды, бюджеты размера), а не её смена, - зато один
язык и готовый код хоста Claude Code экономят месяцы.

## Факты и замеры

MacBook на Apple Silicon, собранное приложение 0.1.0 (`pnpm dist:local`), сразу после
старта, без открытого проекта:

| Что                                                      | Значение |
| -------------------------------------------------------- | -------- |
| Память, сумма RSS 4 процессов (главный, GPU, сеть, окно) | ~340 МБ  |
| Размер Amazing IDE.app                                   | 288 МБ   |
| Размер dmg                                               | 122 МБ   |
| JS окна после сжатия (главный чанк)                      | 309 КБ   |

Сумма RSS завышена: общие страницы фреймворка считаются в каждом процессе. Повторить:

```
ps -axo rss,args | grep "Amazing IDE.app" | grep -v grep | awk '{s+=$1} END {print s/1024 " MB"}'
```

С WebStorm на этой машине не сравнивали. Чтобы сравнение было честным, мерить обоих
одним способом на одном проекте.

## Последствия

- Бюджеты, которые держат оболочку лёгкой: одно окно и один процесс отрисовки; виды
  панелей и GUI провайдеров грузятся лениво (`workbench/views`); рендерер сжимается
  при сборке (`build.minify` в `electron.vite.config.ts`).
- Сборка только под Apple Silicon (arm64): universal удвоил бы размер ради Intel.
- Пересмотреть, если память в покое с открытым проектом и одним провайдером уйдёт за
  600 МБ или если хост провайдеров переедет из Node.
