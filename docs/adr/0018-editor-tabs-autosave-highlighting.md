# 0018. Редактор: вкладки файлов, автосохранение как в WebStorm, подсветка грамматиками shiki

- **Статус:** Принято
- **Дата:** 2026-10-20

## Контекст

Вид «файл» в середине окна был заглушкой с путём выбранного файла. Владелец попросил
настоящий редактор: подсветка всех основных языков, Markdown и `.env`; вкладка на
каждый открытый файл, вкладки переносятся рядами, больше 30 не бывает - новый файл
закрывает самый первый из открытых; закрыл вкладку - открывается та, что была активна
до неё; файлы сохраняются сами, как в WebStorm.

Движок уже выбран - Monaco ([ADR 0005](0005-editor-engine.md)). Открытыми оставались
три вопроса: чем подсвечивать, как сохранять и как не затереть файл, который в это
время правит кто-то ещё. Последнее для этой IDE - обычный случай: рядом работает
Claude Code и пишет в те же файлы.

## Варианты

**Подсветка: Monarch из Monaco** (так было задумано в ADR 0005).

- Плюсы: идёт с Monaco, по замеру ADR 0005 ввод 3 мс на любом файле.
- Минусы: нет `.env`, TOML, Prisma, Vue и Svelte, а JSON без своего языкового
  сервиса (его мы не подключаем) не подсвечивается вовсе. TypeScript раскрашен бедно:
  вызовы функций и типы - ровным текстом. Блоки кода в ленте Claude Code уже красит
  shiki, и один и тот же код выглядел бы в чате и в файле по-разному.

**Подсветка: грамматики TextMate через shiki** - тот же экземпляр shiki и те же
грамматики, что у блоков кода в ленте, построчно, со стеком правил между строками.

- Плюсы: раскраска уровня VS Code, десятки языков, `.env` и Markdown с подсветкой
  языков в блоках кода. Код в чате и в редакторе окрашен одинаково, роли цвета одни
  (`--color-syntax-*`). Грамматика грузится при первом файле своего языка.
- Минусы: разбор TextMate тяжелее Monarch, на огромных файлах это заметно (замер
  ниже). Плюс 10-17 МБ кучи на грамматики и движок регулярных выражений.

**Сохранение: явное (⌘S), со звёздочкой на несохранённой вкладке, как в VS Code.**

- Плюсы: человек сам решает, когда файл меняется на диске.
- Минусы: Claude Code читает файлы с диска - несохранённая правка для него невидима.
  Закрытие вкладки и вытеснение тридцать первой требуют вопроса «сохранить?».
  Владелец просил как в WebStorm.

**Сохранение: само, как в WebStorm.**

- Плюсы: на диске всегда то, что на экране, - и для Claude Code тоже. Закрытие и
  вытеснение вкладки ничего не теряют, вопросов нет.
- Минусы: правка уходит на диск без подтверждения, а значит, может затереть то, что
  в файл за секунду до этого записал кто-то ещё. Это закрывается отдельно (ниже).

## Решение

Подсветка - грамматиками shiki, сохранение - само. Главная причина подсветки: только
так покрываются все языки из просьбы (Monarch не знает `.env` и без языкового
сервиса не красит JSON), а код в чате и в редакторе выглядит одинаково; на вводе в
настоящих файлах замер разницы с Monarch не видит. Автосохранение - просьба владельца
и единственный способ, при котором Claude Code видит то же, что человек. Чтобы оно не
затирало чужие правки, запись идёт только поверх своей версии файла: файл, который
поменяли рядом, не трогается, а редактор спрашивает, чью версию оставить.

## Факты и замеры

Стенд ADR 0005 (`bench/editor`), новый вариант `monaco-shiki` - тот же Monaco, но с
подсветкой кодом IDE (`lib/highlighter.ts` и адаптер `features/editor`). Electron
44.7.2, MacBook Pro M1 Pro, 5 прогонов, медианы. Оба варианта мерились в одном
прогоне: абсолютные цифры в этот день чуть выше, чем в ADR 0005, сравнение - между
строками.

|                                          | Monaco + Monarch | Monaco + shiki |
| ---------------------------------------- | ---------------- | -------------- |
| Ввод, protocol.ts (3 739 строк), на 90%  | 3,2 / 7,8 мс     | 2,9 / 7,7 мс   |
| Ввод, App.tsx (7 796 строк), на 90%      | 3,6 / 8,6 мс     | 3,7 / 8,4 мс   |
| Ввод, сгенерированный файл 2 000 строк   | 3,5 / 8,3 мс     | 3,4 / 8,0 мс   |
| Ввод, сгенерированный файл 200 000 строк | 3,1 / 8,2 мс     | 6,2 / 9,2 мс   |
| Куча JS, App.tsx                         | 18,6 МБ          | 35,3 МБ        |
| Процесс окна, App.tsx                    | 209 МБ           | 241 МБ         |
| Создание редактора, App.tsx              | 90 мс            | 99 мс          |

Ввод - медиана и p95 от нажатия до кадра. Размер сборки у `monaco-shiki` (8 МБ, gzip
1,7 МБ) несравним с `monaco`: в него входят все ~75 грамматик, а грузится только
нужная (TypeScript - около 190 КБ).

Повторить: `cd bench/editor && pnpm install --ignore-workspace && BENCH_ENTRIES=monaco,monaco-shiki
BENCH_ENGINES=monaco,monaco-shiki pnpm bench`.

Проверено в собранном окне (`agent-window.sh`, страница с `file://`): воркер Monaco
грузится, вопрос ADR 0005 про `file://` закрыт - своя схема не понадобилась.

Грамматика собирает вложенные языки один раз, при первой строке: Markdown, открытый
раньше файла на TypeScript, красил блок ```ts одним цветом. Поэтому языки блоков кода
грузятся раньше Markdown (`EMBEDDED_FIRST`), это держит тест
`highlighter.embedded.test.ts`.

## Последствия

- Подсветка одна на окно - `lib/highlighter.ts` (переехала из панели Claude Code).
  Таблица языков - `lib/syntax-grammars.constants.ts` и
  `lib/syntax-languages.constants.ts`, язык файла - `languageOfPath`. Новый язык -
  строка в обеих таблицах, а если у него свои комментарии - конфигурация в
  `features/editor/monaco-languages.constants.ts`. От Monaco берутся только
  конфигурации языков (комментарии, скобки, отступы), Monarch не подключается.
- Тема Monaco собирается из ролей при создании редактора (`monaco-theme.ts`). Фон
  прозрачный - под ним лист середины окна; теней нет. Комментарий - курсивом, как в
  README дизайн-системы, - и в редакторе, и в блоках кода ленты. Липких заголовков
  (строк внешних блоков поверх кода) нет - владелец просил убрать.
- Метки у полосы прокрутки - только то, что ищут по файлу: найденное поиском (акцентом, как
  в тексте) и ошибки и предупреждения (цветами ролей). Вхождения слова под курсором, пары
  скобок и выделения туда не ставятся: серые черточки без цвета читались как шум.
- Меню правой кнопки в коде - наше (`EditorContextMenu`: `Popover` и `Menu`, как у вкладок), а
  не Monaco (`contextmenu: false`). Своё Monaco при `fixedOverflowWidgets` рисует в теневом
  DOM внутри панели редактора: цвета темы (переменные на `.monaco-editor`) туда не доходят,
  меню выходило прозрачным, и край панели его обрезал. Пункты - те же, что были у Monaco
  (правка всех вхождений, буфер обмена, палитра команд), и выполняют те же команды, что
  сочетания; в файле только для чтения правки недоступны. Открывается у курсора мыши, с
  клавиатуры (Shift+F10, клавиша меню, пункт палитры) - под кареткой. Правый клик ловится
  на захвате, раньше Monaco: с выключенным меню он сам ставил бы каретку под мышь при любом
  правом клике (схлопывая мультикурсор) и забирал фокус из полей своих виджетов. Поэтому то,
  что делало его включённое меню, делаем мы: каретка - только мимо всех выделений, поля
  виджетов - системному меню правки, номера строк и полосы - ничему.
- Панели поиска Monaco нет (владелец просил: будет свой поиск IDE). Сочетания его команд
  (⌘F, ⌥⌘F, ⌘G, ⌘E, переключатели флагов) сняты правилами без клавиши и свободны для своего
  поиска, в палитре команд поиска не видно, плашка флагов, которую мультикурсор показывает в
  углу, скрыта (`monaco.css`). Сам модуль поиска остаётся: на нём держится мультикурсор
  (⌘D, правка всех вхождений). Список - `MONACO_FIND_COMMANDS` в `editor.constants.ts`.
- Полосы прокрутки редактора повторяют родные тонкие в соседних панелях: бегунок 6 px
  в 2 px от края, скруглён, под курсором светлеет (`--color-scrollbar-hover`). Рисует
  его вставка в `monaco.css`, а не толщина бегунка в настройках: Monaco сбрасывает её
  на ширину дорожки при любой смене настроек полосы. Классические полосы macOS видны
  всегда, накладные - только когда нужны; режим система меняет на ходу (подключили
  мышь), и редактор узнаёт его по пробе с прокруткой рядом с собой.
- Вкладки - в `state/selection.store.ts` (вкладки и порядок выбора по проекту,
  переживают перезапуск), переходы - `state/editor-tabs.utils.ts`. Вкладка с
  нерешённым вопросом (конфликт, удалён, не записался, файл за проектом) не
  вытесняется, а закрыть её, проект, окно, выйти и поставить обновление можно только
  после общего вопроса (`state/discard-guard.store.ts`, `DiscardDialog` в раскладке окна).
  Не прошла последняя запись при закрытии вкладки - вкладка возвращается с вопросом.
- Запись - `fs:writeFile` с версией, от которой правили (номер файла, время изменения и
  смены метаданных, размер), и отпечатком исходного текста (SHA-256): другая версия и
  другой текст - `conflict`, файл не трогается; версия другая, а текст прежний (touch,
  lint-staged) - запись идёт. Запись безопасная, как в WebStorm (`main/fs/text-write.ts`):
  временный файл рядом с правами старого и переименование; на место - только у файла с
  жёсткими ссылками, чужим владельцем или без права на папку. Версия берётся с самого
  записанного файла. Файл по ссылке за проект сам не пишется - только по ⌘S.
- Пауза автосохранения - секунда; уход из редактора, из окна, закрытие вкладки и ⌘S
  пишут сразу. Записи одного файла идут по очереди. Выход из IDE ждёт ответа окна
  (`editor:command` saveAll, до 2 секунд; окна нет - не ждёт) и всех идущих записей; есть
  несохранённое - выход отменяется и спрашивает (`editor:allowQuit`).
- `fs:changed` несёт список изменённых файлов (`files`) и приходит и на правку
  содержимого. Файл без своих правок перечитывается сам (правка с диска - отдельный
  шаг отмены, перевод строк - вместе с файлом), удалённый закрывается, при своих правках -
  вопрос над кодом. Файл по ссылке сверяется и по настоящему пути, возврат в окно сверяет
  все открытые. Окно передаёт версию, которую знает: та же - текст не пересылается.
- ⌘W вне панели Claude Code закрывает вкладку файла, а не окно.
- Ошибка чтения - не «файла нет»: нет прав - объяснение вместо кода, вкладка не
  закрывается. Канал FIFO в проекте открывается без ожидания и не вешает главный процесс.
- Необычные переводы строк (U+2028) Monaco не трогает (`unusualLineTerminators: off`):
  иначе системное окно предлагало бы переписать файл.
- Буквы, похожие на латинские, не обводятся (`unicodeHighlight.ambiguousCharacters: false`):
  в русском тексте и комментариях рамкой выходила каждая с, у, а, о, владелец просил убрать.
  Невидимые символы (широкий пробел и подобные) обводятся по-прежнему: глазом их от обычного
  пробела не отличить.
- Выделение в редакторе уходит с сообщением Claude Code (строки и текст до 20 000
  символов) - то, что `EditorRef` умел с самого начала.
- Пересмотреть подсветку, если файлы на сотни тысяч строк станут обычным делом и
  ввод в них упрётся в разбор (`monaco-shiki` против `monaco` в стенде), или если
  появится LSP с семантической раскраской, которая сделает TextMate лишним.
