# Окно IDE (рендерер)

Карта частей и кто кого импортирует - `docs/architecture.md`. Ниже - как писать код
внутри. Большую часть держит линтер; правило, которое он не ловит, помечено
«(ревью)».

## Куда класть

| Что                                                   | Куда                                                                                             |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Примитив без контекста IDE (кнопка, поле, меню)       | `packages/ui`, не сюда                                                                           |
| Компонент одной фичи                                  | `features/<фича>/<Компонент>/`                                                                   |
| Данные, нужные двум фичам и больше                    | `state/`                                                                                         |
| Данные главного процесса (проекты, файлы, обновления) | запрос в `state/*.queries.ts` или `features/<фича>/*.queries.ts`, ключ - в `state/query-keys.ts` |
| Интерфейсное состояние одной фичи                     | `features/<фича>/<фича>.store.ts` (Zustand)                                                      |
| Раскладка зон, связка фич между собой                 | `workbench/`                                                                                     |
| Вызов главного процесса                               | только через `lib/ipc.ts`                                                                        |
| Строки интерфейса                                     | `locales/en.json`, в коде - `t('ключ')`                                                          |

Новая папка верхнего уровня в `renderer/src` - сначала запись в `ELEMENTS` в
`eslint.config.mjs` и в таблицу `docs/architecture.md`.

## Компонент

- Папка на компонент: `Name/Name.tsx` + `Name.module.scss`. Остальное - по факту:
  `Name.types.ts` при любом объявленном типе, `Name.constants.ts` при любой
  module-константе, `Name.utils.ts` при любой чистой функции, `Name.hooks.ts` для
  хука длиннее 20 строк или второго хука, `parts/` для подкомпонентов. Типы, константы
  и функции inline в `.tsx` не объявляются (ревью).
- Импорты прямые, без `index.ts` и barrel-файлов.
- JSDoc над экспортом, 1-3 строки по-русски: что это, когда брать, чем отличается от
  похожего (ревью).
- Порядок в теле: состояние и хуки → эффекты → вычисления → обработчики → JSX.
- Обработчики: `handleЧто` локально, `onЧто` в пропсах. Вынес один многострочный -
  выноси все в компоненте (ревью).
- Без `React.FC`, тип пропсов - на параметре.
- Классы по условию - `clsx(styles.a, isActive && styles.active)`. Объектная форма
  `{ [styles.x]: cond }` не компилируется при `noUncheckedIndexedAccess`.

## Меню правой кнопки

Панель - `useAnchoredPopover` (`@amazing-ide/ui/Popover.hooks`), якорь - вкладка или
точка нажатия. Открывать из `onContextMenu` через `openWhenReleased`
(`@amazing-ide/ui/Popover.utils`): на macOS contextmenu приходит при нажатии, и
отпускание закрыло бы только что открытую панель как клик мимо (ревью).

## Когда делить

Лимит - 200 строк на `.tsx` (линтер). Но делить надо раньше, когда компонент
делает две вещи: данные - в хук или `*.queries.ts`, кусок разметки со своей логикой -
в `parts/`, чистые вычисления - в `*.utils.ts`. Признак: имя не подобрать без «и»
(ревью). Не дробить ради дробления: три похожих строки лучше преждевременной
абстракции.

## Состояние

- Одна сущность - один источник. Данные главного процесса не копируются в Zustand и
  не держатся снимком в `useState`.
- Ответ главного процесса на действие кладётся в кэш (`setQueryData`), а не
  перезапрашивается.
- Событие главного процесса тоже пишет в кэш - подписка одна на окно, в
  `app/MainProcessSync`.
- Подписки на события - через `useIpcEvent`, он отписывается сам.

## Стили

- Только `.module.scss` и токены (`var(--...)`). Сырые значения не пройдут stylelint.
- Inline `style` запрещён. Исключение - значение, которое по-настоящему меняется в
  рантайме (ширина при перетаскивании, глубина в дереве): тогда
  `// eslint-disable-next-line no-restricted-syntax -- причина`.
- Hover в `@media (hover: hover)`, active после него, без `transform: scale`.

## Проверка

`pnpm check` из корня. Тронул интерфейс - посмотри на окно глазами: скилл `/dev`
(запуск и скриншот через CDP). Типы и линтер не видят, что панель уехала.
