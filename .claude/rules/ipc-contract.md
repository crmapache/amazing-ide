# Контракт IPC

Всё общение окна с главным процессом описано в `apps/desktop/src/shared/ipc/contract.ts`.
Почему так - ADR 0003.

## Новый канал запрос-ответ

1. Запись в `InvokeContract`: `'область:действие': { request: ...; response: ... }`.
   Без данных - `request: void`. Типы предметной области - в `shared/<область>.ts`.
2. Ключ в объекте `INVOKE_CHANNELS` (иначе не скомпилируется).
3. Обработчик в `main/ipc/register-handlers.ts` (иначе не скомпилируется). Тонкий:
   проверить данные, позвать сервис.
4. В окне - хук в `state/*.queries.ts` (или в фиче, если нужен одной фиче):
   `useQuery` для чтения, `useMutation` с `setQueryData` для действия.

## Новое событие из главного процесса

1. Запись в `EventContract` и ключ в `EVENT_CHANNELS`.
2. Отправка - `broadcast('область:событие', payload)` из сервиса.
3. В окне - `useIpcEvent` в хуке синхронизации, подключённом в `app/MainProcessSync`,
   который пишет в тот же ключ кэша, что и запрос.

## Правила

- `shared/` едет во все процессы: только типы и чистые данные. Ни Electron, ни Node,
  ни React (линтер).
- Имена каналов - `область:действие` в camelCase.
- Ответ на изменяющее действие - новое состояние целиком, чтобы окно положило его в
  кэш без второго запроса.
- Ошибки, которые надо показать человеку, - кодом в типе ответа или события, не
  текстом исключения.
