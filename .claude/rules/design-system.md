# Дизайн-система и стили

Полные правила - `packages/ui/README.md`. Коротко:

- Значения только токенами из `packages/ui/src/styles/tokens.css`: цвет, шрифт,
  кегль, насыщенность, межстрочный, отступы, радиус, слой, тень, длительность и
  кривая анимации. Держит stylelint. Нужного токена нет - добавь его в `tokens.css`
  с понятным именем роли, а не пиши число на месте и не отключай правило.
- Компоненты берут роли (`--color-*`), не палитру (`--palette-*`).
- Прежде чем делать новый примитив - посмотри существующие (список - `packages/ui/README.md`). Отличие в цвете,
  размере, иконке - это `variant`/`size` существующего. Новый компонент - только при
  другой семантике.
- Пакет не знает про IDE и не содержит текста: строки приходят пропсами.
- Подключение - по одному: `@amazing-ide/ui/Button`, типы - `@amazing-ide/ui/Button.types`.
  Новый примитив сразу доступен по такому пути (exports в `package.json`),
  регистрировать не нужно.
- Кнопки и прочий интерактив в шапке окна (области перетаскивания) работают сами:
  `base.css` исключает их из перетаскивания. Свой `no-drag` в компонентах не нужен.
- Классы CSS Modules - camelCase.
- Миксины - поведение без значений (`button-reset`, `truncate`,
  `interactive-surface`, `window-drag-region`). Значение внутри миксина - тоже токен.
- Дизайн-система пока заглушка. Заметное решение по ней (тема, шкала, новый класс
  компонентов) - ADR.
