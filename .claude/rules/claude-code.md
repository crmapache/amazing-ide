# GUI Claude Code

Почему так устроено - ADR 0009, карта - `docs/architecture.md`. Справочник по поведению
и протоколу CLI - amazing-claude-code (`.claude/rules/*.md` там); код оттуда не
копируется.

## Протокол CLI - грабли, проверенные вживую

- **Без `--permission-prompt-tool stdio`** CLI молча отклоняет всё, что требует
  разрешения, и выключает AskUserQuestion и ExitPlanMode. Флаг скрыт в `--help`.
- **На каждый `control_request` - ответ**, иначе ход висит вечно. На
  `control_cancel_request` не отвечать: вопрос снят. Таймеров на вопросах нет - CLI
  ждёт человека сколько угодно.
- **Режим «спрашивать» в новых CLI - `manual`**, режим передаётся всегда: без флага CLI
  возьмёт свой из настроек человека, и панель показывала бы не тот.
- **Готовое сообщение блока (`assistant`) приходит раньше, чем поток закроет блок**, и
  несёт номер 0, а не номер блока потока. Склейку делает `feed/assistant-blocks.ts` -
  по виду блока, а не по номеру.
- **`total_cost_usd` - нарастающий итог сессии**, цена хода - разность. Новый процесс
  (после `--resume`) начинает счёт заново.
- **Контекст хода - по последнему шагу** (`usage.iterations`): верхние поля `usage` -
  сумма по шагам. Окно контекста `result` приносит только в конце хода, поэтому
  `get_context_usage` спрашивается на каждом основном `system/init` (как в ACC, CLI
  отвечает и посреди хода): иначе весь первый ход вкладки кольцо стояло бы на «ctx 0%».
  Окно - модели разговора из `modelUsage`, а не наибольшее (там и модели субагентов).
  Последние цифры едут с вкладкой на диске (`StoredConversation.context`).
- **Имя вкладки от модели** - `generate_session_title` сразу после сообщения человека
  (`conversation/session-title.ts`), а не по концу хода: ход бывает и в час. Спрашиваем,
  пока у вкладки нет имени `llm` или `user`; короткое и служебная команда не называют
  разговор, ответ после /clear отбрасывается.
- **Нулевой ход** (`num_turns: 0`, пустой `result`) после старта с `--resume` - не ход, но
  только без `local_command` и uuid нашего сообщения (`user_message_uuid`): `/compact` и
  `/clear` кончаются таким же пустым итогом, и принятый за рукопожатие он оставлял ход «в
  работе» навсегда (`conversation/turn-command.ts`). Свой учёт хода у CLI - строки
  `command_lifecycle` по uuid сообщения (queued → started → completed | cancelled): итог
  приходит раньше `completed`; команда хода кончилась, а итога нет - ход закрывается без него.
- **Команды «/» знает только процесс CLI.** Свои команды CLI (/compact, /clear, /mcp) -
  `initialize` служебным процессом при старте IDE (`CliAccess`, `askCli`, признак
  `builtin`): разговорный процесс поднимается лишь на первое сообщение, и до него подсказка
  их не знала. `commands_changed` и ответ `reload_plugins` - полный список, им список
  проекта заменяется; приходят только после `initialize` или первого init. Ответ без поля
  `commands` - «новостей нет». Имена списка проекта переживают перезапуск IDE
  (`cli/project-commands.ts`), пояснения на диск не идут.
- **Фоновый субагент** отвечает «Async agent launched…» сразу, Workflow - «Workflow
  launched in background»; это не отчёт. Конец - `system/task_notification` по `task_id`
  (связь с вызовом даёт `task_started`). Агент скилла приходит одним `task_started`, без
  вызова Task; агенты флота workflow в поток не пишут вовсе - только отчёт
  `task_progress.workflow_progress`. Всё это - `feed/agent-tasks.ts`.
- **Человек пишет в чат, пока висит вопрос** - сначала сообщение, потом отказ: в
  обратном порядке модель переспрашивает. Текст при плане - замечание «доработай».
- **Без `USER` в окружении** CLI не находит запись в Keychain и «не вошёл».
  Окружение берётся из login shell (`cli/shell-env.ts`).
- **Аргументы запуска - без переводов строк и кавычек** (батник CLI на Windows режет
  командную строку на переводе строки - опыт ACC).

## Доверие, режим, выход

- **Доверие к папке спрашивает панель** (`settings/workspace-trust.ts`): с `-p` CLI
  этого не делает и сразу исполняет хуки проекта. Доверена - если человек согласился
  в панели или в терминальном Claude Code (`hasTrustDialogAccepted`, папка или
  родитель). Процесс для недоверенной папки не поднимать ни в каком обходе.
- **Режим новой вкладки** (`settings/default-mode.ts`): проект выбирает только
  default, acceptEdits и plan; bypassPermissions - только из настроек человека и если
  нигде не запрещён; auto - из настроек человека или организации.
- **Отправка и очередь - `conversation/outbox.ts`.** Не ушедшее сообщение - в
  очередь, не в никуда; ждавшие уходят раньше нового. Очередь уходит сама, только
  когда нет хода и вопросов: иначе она ответила бы на вопрос субагента за человека.
  Команда (`/compact`) посреди хода или при вопросе ждёт в очереди. Очередь хранится
  на диске. Что её держит, окно видит в `Conversation.queueHold` и подписывает: очередь
  вернувшейся вкладки (`reopened`) и остановленного хода уйдёт после сообщения человека.
- **Выход ждёт процессы** (`ClaudeService.shutdown`, потолок `SHUTDOWN_MAX_MS`).
  Electron превращает SIGTERM в обычный выход, так что `kill -TERM` - честная проверка.

## Новые возможности панели - грабли

- **Имя сообщения - наш uuid** (`conversation/user-message.ts`): по нему откат и форк.
  Написанное посреди хода (`steering`) не откатывается и не форкается.
- **Откат: проверка кода (dry run) → разговор → файлы**; разговор режется с
  `last_seen_user_message_uuid`, идущий ход - с `interrupt_if_running`, на
  `commands_queued` ход останавливается и запрос повторяется. После отката лишний хвост
  хода отбрасывается (`discardStray`) до следующего сообщения. Копии файлов процесс держит
  по настройке человека `checkpoints` (`config/config-files.ts`): выключена - переменной
  `CLAUDE_CODE_ENABLE_SDK_FILE_CHECKPOINTING` нет, диалог говорит «off», а не «не вышло»;
  её смена в `/config` поднимает процессы заново.
- **Форк, который не родился** (нет своего транскрипта), поднимается от источника до
  точки, зафиксированной при нажатии; его лента - источник до точки и шов.
- **Точка форка** (`fork-origin.ts`): «перед первым сообщением» - чистый разговор, а
  сообщения нет в транскрипте (выше сжатия форка оно ищется у источника источника) -
  форк несёт разговор целиком и говорит об этом (`ForkOrigin.whole`, строка `fork-whole`
  под швом), а не открывается пустым.
- **Откат файла хода** (`changes/`, как в ACC) - ханки хода в обратную сторону к файлу,
  каким он стоит сейчас: чужие правки в других местах остаются; строк хода нет на месте -
  отказ, а не перезапись чужого. Точные правки копит `TurnRevert.observe` из живого
  потока (лента держит дифф обрезанным). В конце хода файлы сверяются с диском по копиям
  CLI из `file-history` (форматтер, `sed` агента, большая правка с пустым
  `structuredPatch`) - копия только та, что CLI записал в транскрипт для этого хода.
- **Конфиг MCP CLI читает только на старте**: после `mcp add/remove` процессы проекта
  (у области user - все) перезапускаются, как только свободны (`restartProcess`). Плагины живые процессы
  перечитывают сами (`reload_plugins`). Состояние серверов - `mcp_status` у процесса,
  конфиг с ключами (`env`, `headers`) в окно не уходит.
- **Дети IDE** - всё, что панель запускает (процесс CLI, `!`, разовая команда), - в
  своей группе через `cli/process-group.ts`: выход ждёт их и добивает.
- **CLI в папке проекта - только после доверия**, экраны MCP и плагинов тоже. Своё для
  всех проектов (область user, маркетплейсы) - из домашней папки.
- **Ключи в окно не уходят**: адреса, аргументы и текст CLI - через
  `tools/secret-mask.ts`. Адрес наружу - только `openExternalWeb` (http и https).
- **Отложенный перезапуск** (`applyPendingRestart`) - везде, где разговор
  освобождается, и перед новым ходом; во время отката - нет.
- **Пробы CLI вживую не должны менять настройки человека**: `claude plugin enable` с
  выдуманным именем молча пишет его в `~/.claude/settings.json`. Проверять командами,
  которые на несуществующем отказывают (remove, uninstall), или во временном
  `CLAUDE_CONFIG_DIR`.
- **Лимиты** (`usage/`): `get_usage` не дёргать чаще шага (`usage.constants.ts`) -
  сервер отвечает 429, и CLI пять минут не спрашивает. Процесс разговора без своего
  хода - не источник: его подставленный ответ взялся бы из общего кэша чужого аккаунта.
  Пробовать вживую - в постоянной своей папке конфига, а не в пустой временной.
- **Аккаунты**: обычный вход - без `CLAUDE_SECURESTORAGE_CONFIG_DIR` (удалить,
  а не оставить пустой); своё хранилище - переменная и пустые
  `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN`/`CLAUDE_CODE_OAUTH_TOKEN`. Хранилище не
  переименовывать: имя записи Keychain - хеш пути. Сигнал входа - `auth status`, а не
  выход Терминала. Чей вход - `accounts/identity-probe.ts` (одноразовый конфиг и
  рукопожатие `initialize`, не `get_usage`: тот сервер отбивает после трёх-четырёх подряд),
  а не `auth status`: тот читает общий конфиг. Аккаунт - почта И организация
  (`accountKey`). Своё хранилище удаляется только вместе с записью Keychain
  (`account-drawers.ts`).
- **Хранилище под записью меняют, только если оно само сказало «то же» или «пусто»**
  (`account-twins.ts` `holdsOf`, `account-landing.ts`): повторный вход - новое хранилище под
  той же записью, старое удаляется, живые процессы переподнимаются (`PanelDesk.accountRenewed`);
  держит другого - запись переписывается на месте (`refile`), вход ложится рядом; не сказало,
  чей, - ничего не трогать. Круг экрана: сначала переписывание, потом склейка по свежим ответам
  живых хранилищ (`account-upkeep.ts`).
- **Модель - к каталогу аккаунта до подъёма процесса** (`accounts/model-catalog.ts`, хук
  `PanelHooks.launching` из `spawn.ts`): CLI чужую модель на старте не отклоняет, а падает на
  первом сообщении. Неизвестный каталог - не трогать; свои модели (`prefs.customModels`) - не
  прижимать. Каталог - в памяти (`AccountModels`): с init живого процесса и с экрана аккаунтов.

## Поле ввода - грабли

- **Поле - contentEditable с чипами** (`field-*.ts`, `field.hooks.ts`), не React: узел чипа -
  простой DOM (`ChipRegistry`), его содержимое рисует React порталом (`Composer/parts/FieldChips`).
  Чужие куски (вкладка, отправка, вынутое из очереди) пересобирают поле; своё набранное - нет
  (`lastReported`). Вставка - только `insertAtRange`: пустой текстовый узел на краю ломает набор
  иероглифов. Пока `isComposing`, поле не перестраивается, но правки сообщает.
- **Отмена своя**: браузерная чипов не видит. `historyUndo` из меню перехватывается в фазе
  перехвата и уводится в свою историю.
- **Черновики - `composer.store.ts`** (на диск без байтов картинок: у вставленной есть файл).
  Положить черновик в поле извне - `fillDraft` / `applyDraft` (`field-bus.ts`): одним шагом отмены.
- **Сообщение для CLI собирает окно** (`draft.utils.ts`): цитаты «> » сверху, `[Image #N]` - счётом
  через весь разговор, байты - вложением в том же порядке. Куски (`draft`) и открытый файл
  (`editor`) едут рядом: заметка о файле - отдельный блок `<system-reminder>`
  (`conversation/editor-note.ts`), у команды «/» её нет.
- **Клавиши панели** (Esc - Stop, Shift+Tab, цифры и Enter карточек) - только внутри панели
  разговора (`pane-keys.*`), а не на окне: в дереве и редакторе они не её. Исключение одно -
  «открыть панель» ⌘Esc (`OPEN_PANEL_KEY`): её слушает workbench (`actions/claude-panel.ts`) в
  фазе перехвата с остановкой, иначе Esc того же нажатия остановил бы агента.
- **Картинка за чипом** (`PictureHover`, `picture.*`, как в ACC): превью под курсором в поле,
  ленте и очереди, у такого чипа нет подсказки. Источник решает `chipPicture`: байты чипа →
  файл (выбранная, записанная вставка) → место чипа (`said` - строка транскрипта, `queued` -
  очередь главного процесса). Главный процесс спрашивается, только когда курсор задержался
  (`ASK_AFTER_MS`); читает по пути из чипа только картинку и не больше потолка, большую
  уменьшает (`images/picture-reader.ts`). Клик в ленте и очереди - `PictureLightbox` (редактор
  IDE картинок не показывает), в поле клик ставит каретку. Картинка по «@» и из дерева -
  чип картинки, вид - `kindOfPath`, как у реплея.
- **Ряд кнопок поля не переносится** (`composer-fit.*`, как в ACC): узкая панель отдаёт по
  шагу - имя чипа редактора (выключенный чип целиком), подпись «ctx» у кольца контекста,
  «/», лупу, потом Send и Queue сужаются до первой буквы (`FitLabel`). Меряется до
  отрисовки, шаг за шагом; вернуть шаг - только с пикселем запаса, иначе ряд мигает.

## Служебное поверх разговора (`panel/`) - грабли

- **Разговор зовёт панель через `CliTap.panel`** (`PanelHooks`): живая строка - раньше
  ленты (`line`, true - строка панели, ленте её не нести), итог хода - после `applyResult`,
  ушедшее сообщение - из `writeUserMessage`, выход процесса - из `spawn.ts`. Всё остальное
  панель делает сама (`PanelDesk`), разговор о ней не знает.
- **/btw - служебный запрос `side_question`**, текстом в поток CLI ответил бы «isn't
  available». Свой срок 660 с (`control(…, id)` + `cancelControl`, отмена - ошибкой
  «Side question cancelled»), строка `control_request_progress` в ленту не идёт. Цепочка -
  в главном процессе (`aside-desk.ts`), окну - событием `claudePanel:aside`; в историю -
  только настоящие ответы модели. Спящий процесс поднимается и потом снова засыпает.
- **Моды CLI (2.1.287+)** - строки `system/ui_*` (`mod-lines.ts`): статус и окна -
  `Conversation.mods`, всплывашка - со сроком, лог - отметка `mod`, перерисовка
  выбрасывается. Живут с процессом: выход процесса-владельца их снимает. Вопрос мода -
  номер `toolu_plugin_`, `fromMod`.
- **Быстрый режим** - `apply_flag_settings {fastMode}` (без просьбы CLI под потоком
  отвечает `sdk_opt_in_required`), при подъёме процесса - первой строкой (`spawn.ts`).
  Работает ли - говорит CLI (`fast_mode_state` в init и result). Новая вкладка - без него,
  форк и восстановленная - с ним; модель без него его снимает (`losesFastMode`). Строка FAST
  встаёт заново на каждую новую просьбу (`noteFastAsked`), а не раз на причину.
- **Отказ CLI перейти в режим** (`options.ts`, `settings/mode-refusals.ts`, как в ACC): вкладка
  возвращается к прежнему режиму, панель помнит отказ - bypass на всю панель, auto на модель
  (`ClaudeState.refusedModes`); Shift+Tab их пропускает, меню MODE гасит. Процесс, ушедший до
  ответа, - не отказ.
- **Чип MODEL держит выбор** (`model-watch.ts`): выбор судят по подписи только после
  нового запроса (вернулся вызов, свой ход), модели сравниваются семьёй и поколением, а
  не строкой, третья модель - смена самим CLI. Новый процесс - счёт заново.
- **Продолжение оборванной работы**: решения - чистые функции `carry-ons.ts` (с тестом),
  таймеры - `carry-on-desk.ts`, в памяти (перезапуск IDE ожидание не переживает). Слова -
  в теге `<panel-carry-on reason>`: по нему лента из транскрипта ставит PANEL. Сообщение
  человека или очереди снимает долг; Stop и «Don't continue» - только слова, ожидание
  лимита остаётся тихим и в свой срок отпускает очередь.
- **Select переводит всё** (`account-moves.ts`): идущий ход прерывается, переезд - по его
  концу, упрямый процесс снимается через 8 с; простаивающая вкладка с фоновыми агентами
  меняет процесс сразу. Склейка дублей - `gently`: та же подписка, ход не рвётся. Прерванный
  ради переезда ход подписан «Stopped to switch account» (`interrupt('account')`,
  `TurnFeedItem.forAccount`, у снятого процесса - отметка `interrupted` с detail `account`).
- **Строка SETTINGS** (`settings/account-override.ts`, `repositoryOverrides`): при подъёме
  процесса на именованном аккаунте - имена из обоих файлов репозитория (CLI читает их всегда);
  раз на разговор, заново - на новый набор. Отказ 400 из-за параметра выборки
  (`feed/api-errors.ts`) - метка `sampling` у ошибки хода и объяснение под ней.

## Поиск по разговорам - грабли

- **Ищет главный процесс, окно только рисует** (`main/claude/search/`, как в ACC): индекс слов
  человека и модели по проекту, копия в userData (`claude-search/`). Отметка «докуда дочитали» в
  манифесте сдвигается после записи копии, а не до (`SearchIndex.keep`) - иначе провалившаяся
  запись теряла бы сообщения навсегда. Копия - кэш: смена её формы - `COPY_FORMAT`.
- **Индекс дописывается, а не строится заново** (`text-index.ts`): он живёт в главном процессе, и
  пересборка на каждое обновление живого разговора задерживала бы всё окно. Снятый разговор -
  отметкой, сборка с нуля - когда мёртвых больше живых.
- **Резка слов одна на обе стороны** - `shared/claude-search-words.ts`: главный процесс называет
  найденные термы, лента красит их тем же правилом. Сколько букв красить, решает терм (`paint`).
- **Место находки в ленте - id элемента** (`IndexedMessage.anchor`): у человека - uuid строки
  (живое своё сообщение несёт тот же uuid), у ответа - `id сообщения:номер блока`, где номер -
  счёт блоков всех строк этого сообщения в транскрипте (`transcript-text.ts`, как
  `feed/assistant-blocks.ts`). Поменяется нумерация в ленте - поменять и здесь.
- **Вопрос модели** - `claude -p` в папке корпуса (разговоры текстом), инструменты ровно Grep, Read,
  Glob, поток stream-json ради шагов; запуск - через `tools/cli-run.ts` с `signal` (отмена) и
  `onStdout` (шаги). Отмена помнится с вопроса, а не с процесса (`ai-runs.ts`).
- **⌘F - клавиша панели** (`panel-keys`), не окна: поиск в других зонах не перехватывается.
  Клавиши окна поиска (⌥⌘1-3, ⌥⌘C, ⌥⌘W) - `SEARCH_KEYS`, по ним же подсказки на кнопках.

## Устройство

- Разбор потока - чистые функции в `main/claude/feed/`, тест на настоящей записи
  потока (`feed/__fixtures__/turn.ndjson`). Поменялся протокол - сначала новая
  фикстура (пробник в истории ADR 0009), потом код.
- Окно протокола не знает: рисует элементы `shared/claude-feed.ts`. Новый вид
  вызова - строка в `toolKind` (`feed-rows.utils.ts`), чип (READ, EDIT, BASH…) и его тон в
  `tool-icons.ts`, цель, итог и вывод в `tool-summary.utils.ts`.
- **Время под ответом - всего запроса, а не хода** (`feed/work-clock.ts`, как в ACC): от
  сообщения человека до момента, когда нет ни хода, ни фоновых агентов, без пауз на
  вопросы. Промежуточный ход (ждём фоновых агентов) подписан цифрой CLI. Счётчик строки
  статуса идёт оттуда же (`Conversation.workStartedAt`).
- **id элементов ленты стабильны между живым потоком и транскриптом** (ответ -
  `messageId:номер блока`): по ним закреплённые и место чтения переживают перезапуск.
- **Лента открывается последней страницей** (`history/transcript-pages.ts`, 60 сообщений,
  дальше по 30 через `claude:loadEarlier`); страница режется перед строкой человека, а
  результат вызова, чей вызов на странице выше, ждёт её (`ToolResults`).
- Лента в окне - кэш React Query под `claudeFeed(id)`, патчи по id элементов
  (`applyFeedPatch`). Ленту, которую окно не запрашивало, патч не заводит.
- Раскладка панели повторяет ACC: элементы стоят там же, где в плагине, нарисованы
  нашими примитивами. Разрешение и вопрос с вариантами - над полем ввода
  (`ConversationDock`); решение по плану - кнопками в карточке плана в ленте, как в ACC.
  Исключения - ADR 0022: один индикатор модели, усилия и режима под полем и вкладки без
  цвета группы (выбранная - одним стальным тоном); ADR 0026: кольцо «ctx» - в ряду кнопок
  поля за лупой. Кольца лимитов под полем - как в ACC, все окна в ряд без подписей.
- **Отступы ленты - ритм по виду строки, а не зазор колонки.** Лента (`Feed`) - обычный
  поток: поля соседних строк схлопываются, как в ACC (берётся большее), а во флексе с
  зазором они складывались бы. Ритм вида строки - `ROW_RHYTHM`: `block` (сообщения, ответы,
  карточки) стоит на одном расстоянии `--size-feed-gap` от соседей, `line` (вызовы, агенты,
  мысли, итог хода) - теснее, как пункт списка. От верха панели и от поля ввода лента
  отступает вдвое шире - `--size-feed-edge`. Расстояние между блоками
  меняют одним токеном, а не по паре видов. Новый вид строки без записи в `ROW_RHYTHM` не
  соберётся. У самих карточек вертикальных внешних полей нет - иначе они сложатся с
  полями ленты (строка под `content-visibility` своих полей наружу не схлопывает).
  Боковое поле панели - один токен `--size-panel-gutter` (лента, поле ввода, док, полка
  закреплённых): не писать в них `--space-*` на месте.
- Настройки панели (Settings) - `shared/claude-prefs.ts`, владелец - главный процесс
  (`settings/panel-prefs.ts`, в `claude.json`), в окно - `ClaudeState.prefs`, патчем -
  `claude:setPrefs`. Новое поле - тип, значение по умолчанию, разбор и тест; убранное поле
  из старой записи разбор молча отбрасывает. Держит их и то, что за ними,
  `settings/panel-settings.ts` (режим новой вкладки, `/config`). Размер текста, показания у
  поля, орфография, возврат вкладок, раскладка поля, клавиша отправки и источники настроек -
  не настройки, а постоянное поведение (ADR 0010). Размер текста панели - общий у IDE
  (настройки IDE, ADR 0024): своего масштаба у панели нет, кегли ленты - те же ступени и
  роли, что во всей IDE (`.claude/rules/design-system.md`).
- **Повод позвать человека решает главный процесс** (`calls/`): вопрос, конец хода, лимит,
  доплата, поломка - самый важный на вкладку за такт, выключенный галочкой не зовёт вовсе
  (событие `claude:call`). Окно только играет (`sounds.hooks.ts`): молчит, если человек
  смотрит на эту вкладку, а из звуков подряд пропускает лишь более важный.
- **Слои настроек** (`settings/setting-layers.ts`): процессы разговоров поднимаются без
  `--setting-sources` и читают все слои, как в терминале. Что панель читает сама (режим
  новой вкладки, запрет bypass, `/config`) - те же слои, иначе она назвала бы режим, в
  котором процесс не поднимется.
- **`/config`** (`config/`): `claude -p --no-session-persistence`, команда на stdin, в папке
  проекта после доверия. Отказ CLI приходит с кодом 0 - исход решает перечитанный файл.
  Пишет в разные файлы по ключу: `tips`, `reduceMotion`, `outputStyle` - в
  `.claude/settings.local.json` проекта (проверено на 2.1.293).
- **Шкалы красятся ступенями** (`--color-gauge-1..4`, тона success / warning / high /
  danger у `ProgressBar` и `RingMeter`), а не цветами состояний: режим спокойных цветов
  подменяет роли на корне (`data-gauge-calm`), компоненты о нём не знают.
- Боковое меню - лист `Sheet` поверх панели (`SideMenu`): экран за каждым пунктом,
  родитель экрана - `MENU_PARENT`, вид экрана - `SCREEN_VIEWS` / `SETTINGS_VIEWS`. Строка
  Settings видна, только когда у её экрана есть вид.
- **Полоса вкладок** - `tabs/`: порядок полосы = порядок вставки в Map разговоров
  сервиса (переставить - вставить заново, `TabStrip.reorder`), решения о порядке -
  чистые функции `tab-order.ts`. Группа форков всегда подряд, голова не двигается; группу
  переставляет `claude:moveGroup`, форк внутри группы - `claude:moveTab`. Имя
  вкладки с рангом (`titleSource`): младший не перебивает старший (`tab-names.ts`), имя от
  человека уходит в транскрипт (`tab-rename.ts`). Закрытые - до 20 на проект, под
  прежним id (черновик окно держит под ним же). ⌘W и ⌘R ловит меню приложения и
  отдаёт панели по фокусу (`panel-focus.ts`, событие `claude:panelKey`).
- Процессы CLI гасятся вместе с IDE (`before-quit`) и после получаса простоя. Простой -
  это ещё и ни фоновых агентов, ни флота workflow, ни фоновой команды Bash: вкладка
  выглядит свободной, а сон убил бы их молча.
  Проверяя вживую, не оставлять разговоры в копии окна работающими.
