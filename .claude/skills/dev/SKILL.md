# Осмотр окна

## Главное правило: dev и профиль человека не трогать

Человек сам держит запущенным `pnpm dev` этой IDE и работает в нём. Его процесс и
его папку состояния («Amazing IDE Dev» в Application Support) агент не трогает
никогда: не гасит, не перезапускает, не подменяет `workspace.json`. Однажды такая
подмена уже стёрла список открытых проектов.

Поэтому агент смотрит на **отдельную копию**: свежая сборка текущего кода, свой
профиль в `~/.amazing-ide-agent`, свой порт отладки. Она живёт рядом с dev и с
установленной IDE и ни с кем не конфликтует.

Учти: правки главного процесса (`src/main`) перезапускают dev человека - это
поведение `electron-vite --watch`, и избежать его нельзя. Окно у него при этом
откроется заново со своим сохранённым состоянием.

## 1. Поднять копию

Из корня репозитория:

```
bash apps/desktop/scripts/agent-window.sh start <папка-проекта> [ещё папки ...]
```

Папки откроются вкладками проектов, первая - активная (нативный диалог выбора папки
CDP не нажмёт, поэтому так). Скрипт ждёт, пока откроется порт отладки `5316`.

## 2. Осмотр

```
node apps/desktop/scripts/cdp.mjs screenshot .screenshots/<что-проверяю>.png   # потом Read этого файла
node apps/desktop/scripts/cdp.mjs eval "<выражение в странице>"
node apps/desktop/scripts/cdp.mjs click '<css-селектор>'
node apps/desktop/scripts/cdp.mjs click-at <x> <y>     # клик мимо, в пустое место
node apps/desktop/scripts/cdp.mjs hover '<css-селектор>'
node apps/desktop/scripts/cdp.mjs type 'текст'          # в элемент с фокусом
node apps/desktop/scripts/cdp.mjs key ArrowDown          # Enter, Tab, Escape, Shift, F1-F12...
node apps/desktop/scripts/cdp.mjs key KeyF meta+shift    # сочетание, буква - по клавише
```

Клик - настоящее нажатие мыши, как у человека: панель закрывается кликом мимо, hover
и фокус срабатывают. Но системную обработку окна он обходит: нажатие по шапке, за
которую таскают окно, через CDP дойдёт до страницы, а у человека его забирает macOS.
Поведение кликов по шапке CDP не проверяет - только правила в стилях
(`getComputedStyle(...).webkitAppRegion`).

### Настоящая мышь macOS

Для того, что решает система (hover и клики у областей перетаскивания, «клик мимо» по
шапке, перетаскивание окна), - `real-mouse.swift`. Он на пару секунд поднимает копию
вперёд, ведёт системный курсор и возвращает курсор и прежнее приложение на место.
Работает только с копией агента. Человек в этот момент видит, как двигается курсор, -
предупреди его одной строкой.

```
swift apps/desktop/scripts/real-mouse.swift move 1300,20 1440,20   # печатает «время-мс x y»
swift apps/desktop/scripts/real-mouse.swift click 160,20 800,20
swift apps/desktop/scripts/real-mouse.swift drag 800,20 900,20     # печатает сдвиг окна
```

Что видела страница, смотри журналом: до прогона повесь через `eval` запись событий с
`Date.now()` (pointerover/out, toggle панелей, `:hover` по кадрам), после - забери его
и сверь со временем шагов. Состояние после прогона не показательно: скрипт отдаёт фокус
обратно, и открытые панели закрываются по уходу фокуса.

Опорные селекторы: иконки зон 2 и 3 - `nav button[aria-label="Files"]` и подобные
(подпись = перевод из `locales/en.json`), переключатели в шапке -
`button[aria-haspopup=menu]`, вкладки проектов - `[role=tab]`, папки дерева -
`button[aria-expanded]`, уведомление - `[role=status]`. Главный процесс можно спросить
прямо из страницы: `window.ide.invoke('workspace:get')`.

Скриншот через CDP - это содержимое окна: «светофора» macOS на нём нет.

Копия обычно стоит за окнами человека. Закрытое окно Chromium не рисует, и
`requestAnimationFrame` в нём молчит. Поэтому `agent-window.sh` запускает её с
`--disable-backgrounding-occluded-windows`: покадровые замеры и показ того, что ждёт
кадра, идут и в фоне. Проверить: `eval "document.visibilityState"` - `visible`.

### Окно целиком и эталон - Graphite

Чего CDP не видит («светофор» и рамку окна, системные диалоги и меню), снимай окном
копии через Graphite (`mcp__graphite__*`). В списке окон копия и dev человека выглядят
одинаково (Electron, «Amazing IDE»), поэтому сначала пометь копию заголовком - окно
Electron берёт его у страницы:

```
node apps/desktop/scripts/cdp.mjs eval "document.title = 'Amazing IDE agent'"
```

Потом `list_targets` - окно с этим заголовком, `capture` с `target: "window"` и его
`windowId`. Только окно, не весь экран: рядом открыты переписка и почта человека.

Эталон для переноса из amazing-claude-code - настоящий плагин в JetBrains у человека,
а не только песочница `webview/harness.html`: в песочнице заготовленные сценарии, а не
то, что видит человек. Окно JetBrains снимай так же через Graphite, всё лишнее
закрывай `redact`.

Витрина дизайн-системы (все токены и компоненты) в копии есть, кнопки в шапке у неё
нет - открывается действием поиска: `key KeyA meta+shift`, `type 'Design System'`,
`key Enter` (тем же действием и закрывается, или кнопкой `button[aria-label="Close
design system"]`). Вкладки витрины - `[role=tab]` с текстом «Foundations» и
«Components». Прокрутка - у `[role=region]`.

Меню проекта и ветки - панели в странице: их можно открыть кликом по
`button[aria-haspopup=menu]`, искать и снимать. Системные - только диалоги выбора
папки и «New Project»: они всплывут у человека на экране, их не вызывать.

**Действия, которые меняют реальные проекты** (переключение ветки, новая ветка, push,
update, клонирование), в копии не выполнять: проекты в ней - настоящие репозитории
человека. Диалоги можно открыть и посмотреть, но не подтверждать.

## 3. Изменил код - пересобрать

Копия собирается один раз при старте. После правок: `stop`, потом снова `start`.

## 4. Погасить - обязательно

```
bash apps/desktop/scripts/agent-window.sh stop
```

Гасит окно и удаляет `~/.amazing-ide-agent` целиком. Проверить, что порт свободен:
`lsof -nP -iTCP:5316 -sTCP:LISTEN` - пусто. Скриншоты в `.screenshots/` git не видит,
их можно оставить.
